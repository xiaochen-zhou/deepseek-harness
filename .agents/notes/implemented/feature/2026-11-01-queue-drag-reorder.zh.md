# Agent Note：排队消息可拖拽排序

Status: implemented

[English](2026-11-01-queue-drag-reorder.md) | 中文

## 问题

排队里有多条待发消息时，只能逐条编辑或删除，因此会话执行它们的顺序就是当初输入的顺序。用户最省事的变通办法是删掉一行再重新输入到末尾。

## 决定

把一条排队消息拖到另一行上；指针落在目标行的上半还是下半决定插在它之前还是之后，落点标记线会在松手前显示这个位置。

- `QueueAction` 新增 `{ kind: 'move'; before: MessageId | null }`，`before: null` 表示追加到末尾。控制器在该行自己的待发列表（`next-turn` 或 `next-step`）内做 splice，因此普通消息与 steer 输入各自排序、互不影响。
- 位置按“去掉被移动行之后”的列表计算，所以向下移动会落在标记显示的位置，而不是差一行。
- 请求的位置正好是当前所在位置时不写入 splice；锚点不存在时按 `session/queue-item-not-found` 失败，与其他过期队列编辑使用同一个错误码。
- 只有在队列可变、至少两行、且没有打开的行内编辑或进行中的操作时才允许拖拽：一行不能同时被拖拽和编辑，请求进行中的行也没有确定的顺序可展示。

## 考虑过的替代方案

**每行加“上移/下移”按钮。** 这一行已经有编辑、删除、steer 三个控件，再加两个；而且上移三格要三次往返，拖拽一次就能说明目标位置。

**让用户输入数字优先级。** 这会把队列并不拥有的内部排序概念暴露给用户，还要用户自己计算位置，而不是直接指一个位置。

**靠重新发送来排序。** 删掉这条排队消息再重新入队会重新走一遍附件处理并丢掉这一行的身份，被移动的消息会变成一次新的提交，而不是同一条待发消息。

## 后果

队列的可见顺序就是会话的执行顺序，改变它只需一个手势。队列的待发列表由 Host 持有，所以排序和其他队列编辑一样能跨客户端刷新保留；如果锚点在此期间被删除，操作会明确报错，而不是落到意料之外的位置。

## 测试

`packages/client/ui-conversation/tests/queue-dock.client.spec.tsx` 覆盖队列组件：把一行拖到上一行的下半区会发出一次 `move`、目标是那前一行；拖到下方某行的上半区会发出一次 `move`、目标是该行的前一行；打开编辑或队列只剩一行时不提供该手势。`packages/api/session-controller/tests/commands-queue-attachment.host.spec.ts` 覆盖控制器：向下移动落在标记位置，移到自身不写入 splice，锚点不存在返回 `session/queue-item-not-found`。
